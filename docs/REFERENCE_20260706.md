The official star ratings and max combos in `tests/Files/July2026/reference.json` come from [`OsuDifficultyCalculatorTest.cs`](https://github.com/ppy/osu/blob/2026.711.0-lazer/osu.Game.Rulesets.Osu.Tests/OsuDifficultyCalculatorTest.cs). The accompanying `.osu` files are copied from that tag's `osu.Game.Rulesets.Osu.Tests/Resources/Testing/Beatmaps` directory. The ppy MIT notice for these fixtures is in `tests/Files/July2026/LICENCE.ppy`; the notice for source adapted during the port is in root `LICENCE.ppy`. The inherited fork retains Kionell's notice in `LICENSE`.

`tests/Files/July2026/performance-reference.json` was generated by the pinned C# calculator using [`scripts/reference/OsuReferenceSnapshotTest.cs`](../scripts/reference/OsuReferenceSnapshotTest.cs). It contains intermediate difficulty and PP components for lazer and Classic scores, several mods, a longer map, dropped slider tails, a missed large tick, and Classic cases with explicit legacy total scores including Hidden, Hard Rock, ScoreV2, and the slider-head-accuracy setting. These are test inputs, not retrieved player scores. Copy that test source into the pinned official `osu.Game.Rulesets.Osu.Tests` project and run its `WriteJulyReference` test to regenerate the file.

Run `npm run compare:reference -- --report` to display differences without failing the command. Run `npm run compare:reference` as the parity gate: it checks all cases within `0.00001` stars, exact max combo, and `0.00001` PP/component and legacy score attribute values. The gate currently passes all 29 cases.

Initial upstream baseline: all 8 reference cases have matching max combo, none have matching star rating, and none of the 6 PP cases match. This is expected before the July port. The existing `tests/Files/Standard/Attributes` fixtures cover the older upstream formulas and should not be treated as July results. Their test source is retained as `tests/Ruleset.legacy.ts` and excluded from the default Jest run once July preprocessing changed. `npm run compare:reference` is the required parity gate and is part of `prepublishOnly`.

The active calculator now uses July Aim, Speed, Reading, and Flashlight evaluators, difficulty attributes, star construction, and PP formulas. Slider tails are placed at their true end time; the difficulty wrapper applies official tracking leniency and angle rules. Hit object scale includes the official `1.00041` legacy gamefield allowance, approach time uses integer truncation, and `StandardHitWindows` uses floor-minus-half-millisecond rounding. `tests/JulySkill.test.ts` compares Aim, Speed, and Reading ratings with pinned C# output for NM, DT, HD, and the longer map. The comparison script checks eight star ratings and twenty-one PP scores.

The ported skills and evaluators use the July `ppy/osu` class names (`Aim`, `Speed`, `Reading`, `SnapAimEvaluator`, `FlowAimEvaluator`, `AgilityEvaluator`, `SpeedEvaluator`, `RhythmEvaluator`, and `ReadingEvaluator`). The existing `Standard*` ruleset and score adapter names remain the fork's TypeScript API.

`osu-classes` 3.1 predates the `SliderTailHit` result. Set `score.statistics.set(StandardHitResult.SliderTailHit, count)` when slider tail data is available. If omitted, this fork assumes all slider tails were hit. Classic is represented by the `CL` acronym; its legacy bitwise value is unavailable in `osu-classes` 3.1, so preserve it as an acronym when serializing mod combinations. `SV2` is supported as a ScoreV2 marker. Use `StandardScoreInfo.legacyTotalScore` to enable score-based miss estimation for Classic ScoreV1 scores. The property is distinct from the inherited `totalScore`; without it, combo-based miss estimation applies. Set `StandardClassic.noSliderHeadAccuracy = false` for that Classic option; the setting is preserved by cloning mod combinations. Other Classic gameplay settings do not affect this PP calculator and have not been modelled.

For per-object Speed diagnostics, copy `scripts/reference/OsuSpeedSnapshotTest.cs` into the pinned official test project and run its `WriteSpeedStrains` test. The resulting JSON files are diagnostic output and are not inputs to the regular Jest suite.

For per-object Reading diagnostics, copy `scripts/reference/OsuReadingSnapshotTest.cs` into the same project and run its `WriteReadingStrains` test. Its JSON output is likewise diagnostic only.

For per-object Aim diagnostics, copy `scripts/reference/OsuAimSnapshotTest.cs` into the same project and run its `WriteAimStrains` test.
