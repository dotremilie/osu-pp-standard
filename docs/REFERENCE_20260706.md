The official star ratings and max combos in `tests/Files/July2026/reference.json` come from [`OsuDifficultyCalculatorTest.cs`](https://github.com/ppy/osu/blob/2026.711.0-lazer/osu.Game.Rulesets.Osu.Tests/OsuDifficultyCalculatorTest.cs). The accompanying `.osu` files are copied from that tag's `osu.Game.Rulesets.Osu.Tests/Resources/Testing/Beatmaps` directory. The ppy MIT notice for these fixtures is in `tests/Files/July2026/LICENCE.ppy`; the notice for source adapted during the port is in root `LICENCE.ppy`. The inherited fork retains Kionell's notice in `LICENSE`.

`tests/Files/July2026/performance-reference.json` was generated by the pinned C# calculator using [`scripts/reference/OsuReferenceSnapshotTest.cs`](../scripts/reference/OsuReferenceSnapshotTest.cs). It contains intermediate difficulty and PP components for lazer full combo, one-miss, DT, HD, Classic stable, and a longer map. The generator sets all slider tails as hit and leaves legacy total score unset; these are explicit test inputs, not retrieved player scores. Copy that test source into the pinned official `osu.Game.Rulesets.Osu.Tests` project and run its `WriteJulyReference` test to regenerate the file.

Run `npm run compare:reference -- --report` to display the current differences without failing the command. Run `npm run compare:reference` as a parity gate; it exits unsuccessfully until all cases match within `0.00001` stars, exact max combo, and `0.00001` PP/component values. Classic scoring is reported as unsupported until it is implemented.

Initial upstream baseline: all 8 reference cases have matching max combo, none have matching star rating, and none of the 6 PP cases match. This is expected before the July port. The existing `tests/Files/Standard/Attributes` fixtures cover the older upstream formulas and should not be treated as July results.

The port now has additional July timing, jump, and OD data on `StandardDifficultyHitObject`, plus standalone harmonic and variable-length skill accumulators. `tests/JulySkill.test.ts` checks their basic behavior. The active Aim, Speed, and PP calculators still use the inherited formulas; the reference comparison remains at 0/14 matching cases. The new accumulators are internal until their evaluators and attributes are ported together.

Port order:

1. Align beatmap conversion, hit object preprocessing, and mod parameters with the pinned source.
2. Implement variable-length strains, the Reading skill, harmonic Speed summation, and updated Aim evaluation.
3. Align star rating construction and every reported difficulty attribute.
4. Expand the performance fixtures across more scores and mods, then port PP calculations and stable/lazer scoring semantics.
5. Verify browser packaging and runtime cost before extension integration.
